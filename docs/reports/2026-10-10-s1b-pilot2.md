## 1. A20(1): S1b's Real Crossing Boxes (M3)

### Why a declaration flag alone was not enough

The dynamic crossing view (`grounding_view.derive_dynamic_arms` rule 4) reused the one declared `corridor` box. Every arm consumer read `corridor.center_m` as the junction centre on both axes, with a single `half_length_m`. That describes only a square box at `(c, c)`, which is S1a's origin box. Setting `junction_declared: true` on S1b would have brought back exactly the phantom geometry the A16(iii) guard blocks: the origin box sits over the inter-island corridor and overlaps island_e.

### Design

| Item | Rule |
|---|---|
| Declared field | `SceneGeometry.junction_boxes`: named world-frame boxes `x_min_m..x_max_m`, `y_min_m..y_max_m`. Requires `junction_declared: true`. None keeps S1a byte-identical |
| Anchor | A crossing conflict anchors to the box that BOTH robots' footprints overlap: centre within `robot.half_width_m` (0.09 m) of the box. No such box means the honest `crossing_refused`, and its reason now names the boxes |
| Per-axis geometry | A derived `junction_box` field. `arm_geometry` gives each arm that box's own centre and half-length on the arm's axis; `passer_travel_m` measures a crossing passer to the far mouth of ITS axis. The legacy-path corridor centre reads the yielder's arm geometry |
| Tag | `grounding=dynamic_arms:crossing` plus `grounding=dynamic_arms:junction_box:<name>` |

### The boxes, from S1b's own layout

The islands are island_w x [-1.30, -0.75], y [-0.70, +0.90] and island_e x [+0.25, +0.80], y [-0.90, +0.70]. The band edge is |x| = 2.5, |y| = 1.8.

A box is a lane intersection at an island end: a y-lane (a passage, or the inter-island corridor) meets an x-lane (a north or south gap) where the y-lane stops being walled on both sides. The inter-island corridor is walled on both sides only while both islands flank it, |y| <= 0.70. That is island_e's top and island_w's bottom, so the N and S boxes start there (`scripts/s1b_layout.py crossing_boxes`).

| Box | x range (m) | y range (m) | Centre | Half-extents (x, y) |
|---|---|---|---|---|
| NW | [-2.5, -1.30] (wall .. island_w W face) | [+0.90, +1.8] (island_w top .. wall) | (-1.90, +1.35) | (0.60, 0.45) |
| SW | [-2.5, -1.30] | [-1.8, -0.70] | (-1.90, -1.25) | (0.60, 0.55) |
| N | [-0.75, +0.25] (island_w E face .. island_e W face) | [+0.70, +1.8] | (-0.25, +1.25) | (0.50, 0.55) |
| S | [-0.75, +0.25] | [-1.8, -0.70] | (-0.25, -1.25) | (0.50, 0.55) |
| NE (not declared) | [+0.80, +2.5] | [+0.70, +1.8] | (1.65, 1.25) | (0.85, 0.55) |
| SE (not declared) | [+0.80, +2.5] | [-1.8, -0.90] | (1.65, -1.35) | (0.85, 0.45) |

**Which boxes are real crossings is decided by the routes, not by eye** (`box_ports`, grid router). Each route's run inside a box enters and leaves through a face, or starts or ends at a node inside it. Three or more ports means different paths cross there. Two ports means a bend: every robot through it is on one path, in its two directions.

| Box | Ports used (node-pair routes) | Verdict |
|---|---|---|
| NW | E {E-Wp, N-Wm, N-Wp}; S {N-Wm, S-Wp}; node Wp | crossing |
| SW | E {E-Wm, S-Wm, S-Wp}; N {N-Wm, S-Wp}; node Wm | crossing |
| N | W {E-Wp, N-Wm, N-Wp}; E {E-N, E-Wp}; S {N-S}; node N | crossing |
| S | W {E-Wm, S-Wm, S-Wp}; E {E-S, E-Wm}; N {N-S}; node S | crossing |
| NE | S, W only {E-N, E-Wp} | bend |
| SE | N, W only {E-S, E-Wm} | bend |

The forbidden Wp-Wm leg also runs through NW and SW; it never changes a verdict. `test_s1b_overlay_declares_exactly_the_crossing_boxes_the_layout_derives` pins the overlay to this derivation.

## 2. A20(2): the Ambiguous Arriver Yields Along Its Own Heading (M3)

### Design

| Item | Rule |
|---|---|
| Who | An ambiguous (> 30 deg off both axes) node-handoff ARRIVER, strategy `yield`, derived mode. Rule 1 fixed it as the yielder, so rule 5's handover cannot apply. The occupant's snapped lane does not matter, because it passes. Both robots ambiguous stays a refusal |
| Lane | Rule 3's lane laid along the arriver's heading: `SceneGeometry.lane_heading_rad`. `center_m` / `half_length_m` are measured along the heading (`along_m`), and `corridor.axis` stays the bearing axis for the axis-only consumers (escort headings) |
| Along that axis | Retreat side and axes (`retreat_axes`: retreat = -heading), the room gate (each box clipped to the swept footprint strip, `_heading_lane_room_m`), park floor, `_beyond_corridor_same_side`, the candidate sweep with its unchanged box margins, and the plan-leg room check. A diagonal backup moves on both world axes, so BOTH declared aisle bands apply. The gate scores only the arriver: the occupant never yields |
| Cap (definition) | The arriver's heading must lie within 45 deg of the pair's bearing axis (its component on that axis >= cos 45 deg) AND it must face the occupant. Otherwise the A14(iii) refusal stands. "<= 45 deg off the nearest axis" would never refuse, since an off-axis angle folds into 0..45 |
| Tag | `grounding=dynamic_arms:heading_lane:<id>:<deg>` (degrees off the nearest axis) |
| M4 | Unchanged. `line_hold_yaw` holds the line through the start pose along the START yaw, whatever it is, and the backup counts Euclidean odom distance (`traveled = hypot`), so a 33 deg backup is neither mis-steered nor under-counted. Pinned by a kinematic test at -147 deg |

### The E2 fixture does not flip to executable

The live refusal reproduces on `47fde2d` (5/5 E2 analyses: `ambiguous lane: robot_1 heads 33 deg ... node-handoff arriver`). On the A20 tree all 5 ground a heading lane (`heading_lane:robot_1:33`), and the sweep then refuses them:

- robot_1 sits at (0.649, -1.138) facing -147 deg, toward robot_2 at S, so it backs ENE along (0.84, 0.54).
- Its backup path passes island_e's SE corner (0.80, -0.90). Samples at (0.81, -1.04) and (0.89, -0.98) fall inside the box grown by 0.09 m half-width + 0.05 m `retreat_box_margin_m`; the closest centre-to-corner distance is about 0.12 m.
- No backup length avoids it (the clip is 0.2 m into the path, the band minimum is 0.5 m).

The command now refuses with the measured reason `no executable retreat (robot_1 has no retreat candidate surviving the sweep; robot_2 is the node-handoff occupant, which never yields)` instead of "no retreat room was measured". This is the ruling working as specified, with the sweep as its guard. Making E2 executable would need a smaller margin or a non-heading retreat, and the ruling rejects both.

## 3. A20(3): the Echo Prefers Engaged Latch Pairs (Apparatus)

**The prompt exposes no latch state.** The structured state block carries position, heading, status, goal, task and velocities, and nothing else. So the echo uses the documented heuristic (`mock_backend.echo_select`), never the trigger set:

1. An engaged latch pair is two STALLED robots closer than 0.45 m in the state block's coordinates. 0.45 m is M4's `min_distance_m`; the 0.01 m prompt rounding is far below the 0.29-0.44 m live latch gaps.
2. If there is one, the echo names only latch-pair members, in presentation order, and the yielder is the presentation-first member of the CLOSEST pair.
3. Otherwise the pre-A20 rule applies: every stalled robot, the first one the yielder.

The MC replay now calls the same function (`s1_grounding_replay.echo_names`), so the live echo and the MC cannot drift.

| MC (400 first conflicts) | S1b before | S1b after | S1a before | S1a after |
|---|---|---|---|---|
| Echo yielder outside the first-encounter pair (the pilot-1 "82/400") | **82** | **45** | 69 | 40 |
| ... of which latched to some other robot at the +2.5 s snapshot | 35 | 38 | 36 | 38 |
| Latch-free echo yielder (no robot within 0.45 m) | 47 | **7** | 33 | 2 |
| Involved set equals the encounter pair | 231 | 316 | 152 | 278 |
| Executable rate, all three items | 0.4975 | **0.6125** | 0.365 | 0.4075 |

The 82 drops to 45, not to 0. 38 of the 45 name a robot that IS latched, just not to the first-encounter pair, because a second latch closed within the 2.5 s snapshot delay. The 7 latch-free ones are scenes with no stalled pair under 0.45 m in the prompt, where the fallback rule applies.

**This changes every echo run, S1a included.** The S1a anchor row (n = 6) was collected with the old echo; any S1a comparison against post-A20 echo data must say so (the A16(iv) same-M3 caveat, now also same-echo).

## 7. Findings for the Owner / Step 6

1. **First S1b resolution events, but no resolution.** E3 executed 4 yields (gate_admit -> gate_release), and every one ended on the 45 s backstop with no task progress. "Executed yield" is not a sufficient success measure on S1b; the headline needs a task- or passage-completion qualifier.
2. **Period-2 dispatch livelock** (E3). The current identical-dispatch detector cannot see it. Proposed Step 6 item: loop detection over the last k dispatches, and suppression keyed on the cluster rather than on one command.
3. **Echo x rule-1 interaction.** With two latch clusters, the node-handoff search over every involved robot moves the yield away from the echo's closest pair. If the echo is meant to stand in for "the trigger's conflict", it should name ONE cluster (the closest pair's connected component), not every latched robot. Apparatus fix, owner call.
4. **A20(2) cap is binding live** (E4, 4/6 analyses). That is consistent with the ruling. The refusal text should name the cap (residual).
5. **A20(1) works live**, with 5 box-N groundings. But box-N yields FAILED 3 of 4 after the first, inside an oscillating trio, so the crossing frame is real while the retreat room is contested by moving traffic (pilot 1 finding 3 again).
