## Prompt v3.4 (Ruling 1)

**Change.** In `reasoning/vlm/prompt_builder.py`, the template's closing block is replaced. That block ran from `Answer using the following format:` through `<think> … </think>` to `Immediately after the </think> tag, write ONLY …`. The replacement is the one sentence the roster diagnostic's condition B answered 3/3: `Write ONLY the final JSON object, with no surrounding text or markdown.`

**What stays the same:**

- The bounded `reasoning` field, first in the JSON schema, is unchanged.
- `prompt_version` stays 3, under the pre-freeze re-pin-in-place exception.
- The now-dead `think_geometry_step` keys are deleted from `_GEOMETRY_ON` and `_GEOMETRY_OFF`. `str.format` ignores extra keys silently, so leaving them would hide drift.
- The version comment carries the lineage v3.0 `22baf2df…` → v3.1 `42463ce2…` → v3.2 `c3fb9fcf…` → v3.3 `769802f0…` → v3.4 `6d08540f…`.

**Parser.** `output_parser._extract_json_object` strips `<think>…</think>` with a non-greedy `re.sub`, which is already a no-op when the block is absent. No code changed, so v1/v2 replay parsing is untouched. The replay below parsed bare JSON (Sonnet, DeepSeek, gpt-5.1) and fenced JSON (ER-2, gpt-4o) with no new code path.

## Refused-Attempt Usage (Ruling 3)

**Change.** `ReasonerDiagnostics.attempt_token_usage` is new. It is a list with one entry per attempt, in call order. An entry is `None` when the attempt raised a transport error or the provider reported no usage.

- `Reasoner.run` appends each response's `token_usage` before parsing, so a refusal's billed usage is kept.
- The success path records the full list. Refusals before an answer are no longer lost: under v3.3 the s43 grey-image answer carried only the last attempt's usage.
- The failure path now sets `token_usage` to the final attempt's usage and records the list.
- `write_reasoner_log` writes `attempt_token_usage` only when a refusal or fallback occurred. A trace with neither stays byte-identical, following the existing convention.
- **Cost = sum of `attempt_token_usage`**. Never add `token_usage` to it, because the final attempt is already in the list (field comment in `models.py`).

**Where it surfaces.** The decision artifact dumps `diagnostics` whole, so `attempt_token_usage` appears in every M5 decision JSON under `diagnostics`.

**Pins** (`tests/unit/test_model_wiring.py`, through the real `AnthropicBackend` with a sequenced fake `requests.post` carrying HTTP-200 `stop_reason: "refusal"` with usage):

| Test | What it fixes |
|---|---|
| `test_terminal_refusal_records_every_refused_attempts_usage` | 4 refusals with distinct `input_tokens` 4001–4004, all recorded in order; a last-only implementation fails it |
| `test_terminal_refusal_records_the_final_attempts_usage_as_token_usage` | failed-path `token_usage` = attempt 4 |
| `test_answer_after_refusals_keeps_the_refused_attempts_usage` | refused, refused, then answered on the grey attempt 3: `[4101, 4102, 1500]` |
| `test_transport_error_attempt_records_no_usage` | `[None, {...}]` |
| `test_reasoner_log_records_attempt_usage_when_an_attempt_was_refused` / `…_omits_…_without_a_refusal` | the JSONL trace convention |

**Open item, not in scope:** stage 2 (`RetreatChooser` / `RetreatChoiceResult`) records no token usage at all, refused or answered. Stage-2 cost therefore stays an estimate.
