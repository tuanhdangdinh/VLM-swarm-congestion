## 1. A19 Exemption Scope (M4)

### The futile case, reproduced

A2 of the S1a anchor dispatched an echo yield (robot_1 yields, robot_5 passes) 0.6 sim-s after robot_1 latched to a THIRD robot, robot_2, at 0.38 m. The safety monitor's exemption was pair-scoped (`robot_1+robot_5`), so the robot_1+robot_2 min-distance latch kept zeroing the backup and the bus FAILED the yield ~15 sim-s later with no motion.

The fixture `tests/unit/data/a19_exemption/a2_seed4_c2fcb3ed.json` is the real A2 M1 scene rows (35.0-53.0 sim-s) and the artifact's dispatched command. Replayed through `SafetyMonitorNode` on `56836a4`, robot_1 is latched in every row after ACTIVE (6 of 7 fixture tests fail). After the fix robot_1 is free and robot_2 is still held.

### Design

| Item | Rule |
|---|---|
| Who | Only the robot whose ACTIVE command is a clearing action (`yield`, `reverse`). The passer's `temporary_wait` and every Nav2 leg never arm a waiver |
| When | Captured once, on the first scene tick after the clearing command is known, from the PREVIOUS evaluation's latched pairs (the latches standing at command start). Frozen: a latch formed during the window still fires |
| Toward whom | Robots the commanded robot was ALREADY latched with, minus its own command's robots, crossing order and same-plan partners (their pairs keep today's admission rules). Not a radius: only pairs the latch rules engaged |
| How | ONE-SIDED (`ClearingExemption.waivers`, ordered `(clearing_robot, partner)`): the pair still engages and still holds the partner, so the partner cannot drive into the backing robot. Applied in the proximity rule and the STALE remembered-distance rule |
| Until | Per partner, until the pair is no longer engaged (fresh >= 0.45 m, or outside the STALE band); a terminal status drops all |
| Floor | The hard-contact floor latches BOTH robots of a waived pair below `hard_contact_floor_m` when enabled. It is 0.0 on the VM, so there is no live floor backstop; the GT minimum gap is reported per waiver |
| Byte-identity | With no third-robot latch the waiver set is empty, `ClearingExemption` compares equal and no log line changes. All 202 pre-existing safety-monitor and floor tests pass unmodified |
| Logs | `latch waiver armed robot= command= partners=`, `latch waivers changed waivers=a>b`, `latch waiver released ... reason=separated` |

Commit `4e1b5bf`; tests `tests/unit/test_a19_exemption_scope.py` (28). The fixture proves the latch flips, not motion; live behaviour is in [§6](#6-a19-exemption-live-behaviour).

## 2. A16(iii) Crossing-View Guard (M3)

**Status at the start of this wave: NOT shipped.** The resolvability wave's note lists the S1b seed-22 crossing case as found-not-fixed, and `derive_dynamic_arms`' crossing branch had no declaration check. It is implemented here (`b6aa970`).

- **Field.** `SceneGeometry.junction_declared` (default False), read only by the dynamic-arms view.
- **Behaviour without it.** A crossing YIELD refuses: `yield refused: no declared junction: <a> runs along <ax> and <b> along <bx> (a crossing), but the scene declares no junction to anchor the arms to; no retreat room was measured`, tag `grounding=dynamic_arms:crossing_refused:<a>,<b>`. It is a pure `yield refused:` fan-out, so `refusal_no_action` withholds it. A `reverse` keeps the declared geometry (the rule-6 precedent), tagged `grounding=dynamic_arms:crossing_undeclared`.
- **Declarations.** S1a's overlay (`mapd_5.yaml` header) declares `junction_declared: true`; S1b's does not. On the VM, the S1a regression overlay is `s1a_orch_seed5_a19.yaml` = `s1a_orch_seed5.yaml` + that one line.

**400-conflict MC replay, per-seed command diff against `56836a4`:**

| Floor | Commands changed | Executable rate | Transitions | 0.00 m refusals |
|---|---|---|---|---|
| S1a | **0 / 400** (byte-identical) | 0.365 -> 0.365 | none | — |
| S1b | **57 / 400** = exactly the crossing-branch conflicts | 0.515 -> **0.4975** | 7 executable -> refused (yields grounded on the S1a-anchored crossing frame), 50 refused -> refused with the true reason | 1 -> 0 |

The pilot prediction moves from 0.76 to **1 − 0.5025² ≈ 0.75** (recorded in the VM NOTES before episode 1). Tests `tests/unit/test_s1_crossing_guard.py` (6).

**Verdict: PASS.** The dispatched-fallback loop is gone, and not merely withheld: the new M3 grounds this conflict as a real yield instead of `yield=infeasible`, so no empty reroute arises at all. The suppression and `refusal_no_action` arms then hold the two later (refused) analyses.

**Caveat.** A3r withheld 0 empty reroutes, so the `empty_reroute` withhold path itself is still not live-verified: A16 removed the cause upstream (the conflict now grounds a yield), and A3 has lost its power as that path's named regression scenario. The unit pins (`tests/unit/test_s1_resolvability.py`) remain its only evidence.

**What the one yield did.** robot_1 backed up 0.63 m of 1.40 m (GT x −1.82 -> −1.19), which cleared its r1+r5 latch (the 3.9 s transient interval). The bus FAILED the yield ~44 sim-s after ACTIVE; the passer's wait COMPLETED, robot_5 drove into the cluster, and the floor gridlocked at 62.9 rel-s. This is a new failure mode for Step 6 (n = 1): **the retreat sweep clears the backup path against the snapshot, but the path is shared with moving traffic** — at grounding (scene 39.9 sim-s) robot_2 sat 1.96 m along and 0.35 m lateral to robot_1's backup line, outside the footprint-wide swept corridor, and was driving west on a parallel track ~0.34 m off it; the 0.45 m latch radius, which is wider than the swept footprint, closed on the two moving robots at 47 sim-s.

### Why the MC expectation did not transfer

The ≈ 0.75 is an average over 400 MC first conflicts. Running the same MC on the two LIVE seeds (`s1_mc.run_episode`, the replay's grid router, Δ 2.5, a snapshot 2.5 sim-s after the first encounter) gives a per-seed prediction:

| Seed | MC first encounter | Live first encounter | MC echo stalled set -> grounding | Live first analysis |
|---|---|---|---|---|
| 1 (E1) | r3+r4, 15.2 rel-s | r3+r4, 18.1 rel-s | {r2 (dwelling at N), r3, r4} -> yielder r2 -> node handoff -> **crossing refused (guard)** | 20.2 rel-s, yielder robot_1 (settling at E) -> crossing refused (guard) |
| 2 (E2) | r1+r5 head-on, 13.2 | r1+r5, 14.3 | {r1, r5} -> **executable yield** (handoff r1->r5, lane x) | 16.2 rel-s: robot_2 had reached S 0.5 s earlier and joined the involved set; the handoff re-paired robot_1 with robot_2, and robot_1's live heading was 33° (3° past the snap) -> ambiguous-arriver refusal |

So the MC predicted one executable first-conflict yield in two, not ≈ 1.5. Live lost that one to timing (an arrival half a second before the trigger) and to a heading DWB had bent off the MC's axis-aligned route.

**The E1 mechanism is in the MC too.** The echo names every STOPPED/SLOW robot in id order and makes the lowest-id one the yielder, so a robot dwelling at, or settling onto, a task node is named. Across the 400 S1b MC first conflicts the echo yielder sits outside the encounter pair in **82/400 (20.5 %)**, and the stalled set equals the pair in only 231/400. Live, it sat outside every latch pair in 6/8 E1 analyses:

| Episode | Analyses whose echo yielder was in NO latch pair | What was latched |
|---|---|---|
| E1 | **6 / 8** (robot_1 at E ×3, robot_2 arriving at Wp ×2, robot_1 at N ×1) | r3+r4 (later +r5) in the west passage |
| E2 | 0 / 5 (robot_1 is latched to r5, but the node handoff re-pairs it with robot_2) | r1+r5, then the S pile-up |
| A3r (S1a) | 0 / 3 | — |

When the yielder is outside the latch, the anchor pair is a far-apart pair whose headings differ, for example robot_1 at E (x ≈ 2.2) against robot_3 in the west passage (x ≈ −1.6). The view calls that a crossing, and with no declared junction it refuses. This is the A12(i) echo apparatus, not a model decision.
