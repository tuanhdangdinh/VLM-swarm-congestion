**Tree audited:** `/Users/tuanhdangdinh/Documents/vgu-vlm-swarm-v2`, branch `feat/prereg-v2-composite` (HEAD `941c1c3` at audit time). Read-only; no files modified.

**Classification:** (A) registered + provenance-tracked; (B) safety/robustness override with logging; (C) test-only or measurement leak risk; (D) UNREGISTERED FORCING.

**Global verdict:** No category-D finding in any layer. No resample-until-accepted loop exists; core decision fields are never rewritten; failed validation yields `decision=None` with nothing substituted; prompts leak no answers; sampling is pinned per arm and echoed in every artifact; every strategy/role substitution found is tagged or provenance-split; the scorers are mechanical, GT-anchored, and adversarial to the project's own results. ### Verdict (M2)

**No Category-D (unregistered forcing) findings.** The M2 layer does not railroad the model: no resample-until-accepted-answer loop exists (the only content-conditioned retry is the refusal path, bounded and flagged per attempt); core decision fields are never rewritten; failed validation yields `decision=None` up the stack with nothing substituted; voting tie-breaks cannot introduce an uncast answer; sampling is pinned per arm and echoed in every artifact. All places where the system *does* override or substitute for model output are downstream M3 grounding actions carrying provenance tags (`retreat=default:*`, `m3_default`, `strategy=aliased:*`, `roles=legacy-convention`, `yield_robot=regrounded`), and the most aggressive one (yield swap) ships OFF.

**Three most important findings for the committee:**
1. **Refusal mitigation (finding 2)** is a semantic-content-conditioned retry that swaps the image stimulus mid-request. It is registered, bounded, and per-attempt logged — but any headline accuracy number must be reportable split by `refusal_attempts`/`image_fallback_used`, because mitigated decisions saw a grey image, not the scene.
2. **The M3 default-substitution family (findings 8, 9, 11, 12)**: model output can be replaced or re-grounded downstream (geometry-max retreat, derived default plan, first-robot yielder, swapped yielder). All tagged — so the defense is that analyses MUST condition on the provenance/degradation tags; any metric that credits the VLM without filtering `m3_default`/`retreat=default:*` rows inflates the model's apparent competence.
3. **Mock/forced-order harnesses (finding 6)** are distinguishable from live runs only by the `backend_id` field (and `MOCK_DECISION_FILE` in run metadata). Runtime leak into a live run requires an explicit env/config flip and is well-guarded; the residual risk is analytic — any aggregation over `data/logs/vm_runs` that fails to filter `backend_id != "mock"` would mix scripted decisions (including `t2b_oracle_order_once.json`-style injected answers) into model statistics.

### Verdict (M3/M5)

**The grounding layer does not take credit for decisions the model didn't make** on the dispatch/artifact path: every strategy or role substitution found is either tagged in `degradations`, carried as a reason string the artifact lifts to top level, or split out by the three-way plan provenance, and the engine explicitly refuses to let a model plan silently override the model's own decision fields (inconsistent → m3_default) or to drive dispatch at all (`dispatch_matches_plan` exists precisely because it doesn't).
