# New-VM Environment Audit: Does the Environment Explain E2's Early Latch Freeze?

**Prepared:** 2026-10-09

**Revision history:**

- Initial draft: version inventory against the old VM, seed-draw check, offline trajectory forensics across both VMs, and a Nav2 1.3.13 vs 1.3.12 container A/B on the E2 episode (environment-only changes, echo mock, $0 API).

---

## Summary

**Verdict: the scene caused it. The environment is exonerated.** E2's all-robot latch freeze is a property of seed 2's task draw on the S1 floor. It does not come from the new VM's packages, DDS setup or physics.

- **The "known delta" is unsupported.** No record anywhere shows the old VM running Nav2 1.3.12. Its `vgu_ros` was built on 2026-09-25 from the unpinned apt recipe, and packages.ros.org main had carried 1.3.13 since the 2026-09-11 sync. So the old box most likely ran 1.3.13 as well. That is **inferred** from the apt timeline; the old container was never dumped. The prereg A9 "1.3.12" names upstream source that was read, not an installed version. `bt_action_node.hpp` is unchanged 1.3.12 → 1.3.13, so A9's halt() mechanism holds on both versions; only its label is off.
- **Cross-VM motion and perception match.** On seed 1, the same robots on the same USD drove the same free-flow first legs on both VMs: at most 1.2 cm path deviation and at most 0.14 s time lag over 0.8–2.2 m. Corner clearances agreed to 2–6 mm. M1 position error was a 4–6 mm median with 0 STALE on both boxes. The smoke pair's "1 s earlier" arrivals are a 1.7 s startup offset. Measured from motion onset, the new box is 0.5–0.7 s slower, inside old-VM run-to-run spread.
- **The seed-2 draw is byte-identical everywhere,** and it is a rare convergence: **4 of 5 robots draw S as their first task while robot_5 starts on S** (p = 1/144).
- **The A/B: E2 reproduces twice.** A 1.3.13 repeat and a Nav2 1.3.12 container run both REPRODUCE E2 under the pre-registered rule.

**What 1.3.12 → 1.3.13 changes** (19 commits, `gh api …/compare/1.3.12...1.3.13`). In components this stack runs:

- `controller_server`: goal-reached is now checked before the velocity publish (#6261), and an end-pose TF failure now throws (#6285).

- BT engine: a `NodeExecutionError` catch (#6181).
- `validate_messages`: map checks.

There are **no changes** to:

- DWB critics or trajectory generation;
- NavFn;
- obstacle, inflation or static layer cost semantics;
- the progress and goal checkers;
- the collision monitor.

The aggregate compare lists 172 files (`nav2_compare_files.txt`), and it confirms the list above.

- **Behavior tree.** The only `nav2_behavior_tree` plugin-header edits are doxygen comments, plus 12 non-comment lines: port-default literal types (`1` → `1.0`, `std::string("…")` → `"…"`) in clear-costmap, battery and transform-available. `bt_action_node.hpp` is **unchanged**, so A9's "`bt_action_node` halt() cannot cancel a goal whose handle has not spun" holds on 1.3.13 as well.
- **Everything else.** DWB critics, `dwb_core`, `dwb_plugins`, NavFn, the collision monitor and `costmap_queue` change only `package.xml`, plus one DWB critic **test** file.

No listed change can bring robots closer mid-aisle. The min-distance latch itself is M4 project code (`safety_monitor_node`, fed by `/perception/scene_state`), not Nav2.

## 4. Verdict

**Scene/regime-caused. The environment is exonerated.** Five checks exonerate it:

1. **Package delta.** The supposed Nav2 1.3.12 → 1.3.13 delta between the boxes is unsupported: both ran 1.3.13 source. Even so, an explicit 1.3.12 container reproduces E2 inside the 1.3.13 run-to-run variance. The upstream diff has no mechanism for closer mid-aisle approaches.
2. **Cross-VM motion and perception.** On identical scenarios, the two VMs produce the same trajectories and the same M1 quality:
   - the seed-1 free-flow first legs agree to ≤ 1.2 cm and ≤ 0.14 s;
   - the corner clearances agree to ≤ 6 mm, including the SW-rack wedge on both boxes;
   - the smoke onset-aligned arrivals are within old-VM repeat spread;
   - M1 error is a 4–6 mm median with 0 STALE on both boxes.
   
   That covers the residual deltas (driver 595.84 → 595.91.07, pydantic 2.13.5 → 2.14.0, container rebuild) **for free-flow motion and perception on seeds and cells run on both boxes**. Seed 2 itself was never run on the old box.
3. **DDS.** The Isaac process and all 7 sampled container nodes run the UDP-only profile, verified live.
4. **Draw.** The seed draw is byte-identical across interpreters, pydantic versions and boxes, and runtime consumed it unchanged.
5. **Precedent.** The old VM's own S1 pilot froze all 5 robots under permanent latch pairs on a comparable time scale. The latch gridlock class predates the new box.

**What does cause E2.** Seed 2 sends 4 of 5 robots to S (p = 1/144) while robot_5 leaves S. Three closed-loop runs then produce the same freeze:

- the r1/r5 head-on in the S strip at about start + 18.5 s;
- robot_2's SW-corner graze;
- the W-arm 2/4 pair;
- the 3/5 or 1/3 completion of the cluster.

This is the S1 latch-cluster residual of `2026-10-09-s1-e2-e3.md` §4 under a worst-case draw. It is not a box artifact.

**Old-VM A/B.** It is **not worth asking the owner to power the old VM on.** A true cross-box E2 would test only the driver and pydantic deltas, which the seed-1 cross-VM kinematics already cover end to end. Reconsider only if a future cross-box comparison shows a kinematic divergence (more than about 2 cm or 0.2 s on matched free-flow legs).

**Residual caveats.**

- The cross-VM A/B is on seed 1 and the smoke cell, not on seed 2. Seed 2 was never run on the old box.
- Old-VM package versions are inferred from apt and PyPI timelines; they were not dumped.
- The registered "free-flow equivalence across boxes" OPEN item is **narrowed, not closed.** First-leg kinematics match, but no free-flow harvest was run.
- The mirror asymmetry behind robot_2's tighter SW-corner track (0.040 m vs the 0.107–0.113 m Wp→N mirror) is deterministic but unexplained. It is a scene/planner question for Step 6, not an environment one.
- Apparatus note: under the 1.3.12 / BT.CPP 4.9.0 pin, `bt_navigator` activated with no plugin-load errors. The A9 "`bt_action_node` halt()" path was not exercised under either version, because no Layer-2 command was dispatched (every refusal was withheld).
